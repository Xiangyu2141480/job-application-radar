# 秋招雷达

本地优先的秋招投递状态监控与巡检看板。它面向秋招、实习和社招求职者，解决“企业不主动通知淘汰或挂起，只能反复登录各个平台查看”的麻烦税：把投递记录、最后检查时间和状态变化集中在一处，按沉默时长生成巡检优先级。

## 项目价值

- **看清全局**：总投递、进行中、待跟进、疑似沉默、已结束和阶段分布一目了然。
- **降低漏查**：按 7 / 14 天未变化自动预警，并生成按紧迫度排序的巡检队列。
- **保留过程**：每次状态更新或确认“无变化”都会写入时间线。
- **真正本地优先**：无后端、无账号体系，数据默认只存在当前浏览器。
- **诚实的能力边界**：当前版本不伪装成跨站自动监控，也不绕过平台登录、验证码或反爬策略。

## 主要功能

- 投递记录增删改查：公司、岗位、平台、原始链接、投递日期、当前阶段、最后检查时间和备注。
- 阶段覆盖：待投递、已投递、笔试、面试、意向、Offer、简历挂、测评挂、一面挂、二面挂、三面挂、终面挂、其他挂、已撤回；各类“挂”和已撤回均计为结束态。
- **待投递队列**：可先收藏计划投递的机会并暂不填写投递日期；更新到“已投递”或后续阶段时必须补充日期。
- 待投递可参与阶段筛选、Dashboard 统计及 CSV 导入导出；空日期不会触发沉默预警，并会优先出现在巡检队列。
- 状态变化历史：记录旧状态、新状态、发生时间和说明。
- 搜索与阶段、平台、预警筛选。
- 巡检队列：打开原始投递链接，返回后确认无变化或更新状态。
- CSV 导入、导出和模板下载，带字段与数据校验。
- 兼容旧数据：localStorage、JSON 备份、CSV 与检查结果中的旧阶段“已拒绝”会自动迁移为“其他挂”，记录及状态历史不会丢失。
- JSON 完整备份与恢复；清空数据二次确认。
- 可明确加载、识别和删除的示例数据。
- 预留 `ConnectorAdapter` 与版本化 `CheckResult` JSON 检查结果导入接口。

## 本地运行

需要 Node.js 18+ 与 pnpm。

```bash
pnpm install
pnpm dev
```

浏览器访问终端提示的本地地址（默认 `http://localhost:5173`）。

## 生产构建

```bash
pnpm build
```

构建产物生成在 `dist/`，该目录不提交 Git。

## 数据隐私

投递数据通过 `localStorage` 保存在当前浏览器中，不会上传到服务端。清理站点数据、重置浏览器或更换设备前，请在“数据与接入”页面下载 JSON 备份。部署站点的访问者彼此不会共享数据。

## 后续平台接入路线

当前 MVP 只提供人工巡检和检查结果导入，不会自动登录或抓取招聘平台。后续计划通过用户已登录的 Ego Lite 浏览器，为牛客、BOSS 直聘、字节、腾讯、阿里等平台逐个录制稳定、可审阅的巡检流程，并通过版本化 Adapter 将结果导入。所有自动化都应尊重登录状态、平台规则和用户确认，不把“待接入”宣传成“已自动监控”。
